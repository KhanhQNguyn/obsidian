# 2026-09-30

## Diary

**Business Challenge research day** - goal: improve the solution we already have and understand the manual process behind the 380,000 VND / 1.8-4.6 days. Full notes: [[solution-usp-research]] and [[underwriting-process-analysis]]; parent: [[business-challenge-2026]].

**Where we start.** Problem statement: HLBVN's manual, bureau-only underwriting (380,000 VND, 1.8-4.6 days per application) only works for customers with a credit file; 64.5% of point-of-purchase applicants have none (20.5 + 15 + 14.5 + 14.5 from the case mix, [[business-challenge-2026]] §4.8). Current solution: a pre-computed cash-flow credit limit refreshed weekly (checkout = lookup) plus income-linked repayment.

**1. What the current process is** (details + step table in [[underwriting-process-analysis]] §1)
- Case says: redirect to separate flow -> paper/scan documents -> verification -> credit officer checks against CIC -> decision after days; centralized manual review; cost is fixed per application whatever the loan size.
- Public Vietnamese bank practice matches (documents, verification calls, CIC lookup, 3-5 working days).
- The case gives only the totals, **not the breakdown**. My split into 5 steps (docs, queue, verification, review, sign-off) is an assumption that sums to 380,000 and 1.8-4.6 days. Ask BTC for the real one.

**2. What it costs**
- 380,000 is 23.75% of a 1.6M loan but 0.42% of a 90.1M loan. Under an assumed 24% APR / 3 months, the review alone breaks even only above ~6.3M VND ticket.
- Rejected applications cost the same, so cost per *funded* loan is higher than 380,000.
- Potential loss = abandonment at checkout + wrongly rejected gig/first-time/MSME customers + leakage to informal credit + selection bias (we never learn from those we reject).

**3. How to improve it** (step-by-step table in [[underwriting-process-analysis]] §4)
- eKYC + consented data connection instead of paper; straight-through path inside limit; weekly scorecard so the officer only sees flagged cases; pre-approved limit at checkout.

**4. Build on existing vs. brand-new?** Verdict: **hybrid**. Keep core banking, the existing STP path for salaried-with-history, CIC integration and the manual lane (as fallback and for big tickets). Add a thin new layer beside it: consent + data connectors, scorecard, limit engine, checkout decision API; buy eKYC/aggregation. A full rebuild fails the "deployable in 6-12 months, defendable to a credit committee" test in HLBVN's letter ([[business-challenge-2026]] §4.2). Reasoning in [[underwriting-process-analysis]] §5.

**5. Better solution from what we have** (details in [[solution-usp-research]])
- Gaps in our current idea: customers are invisible until they apply, no default labels for rejected groups, limit can be stale at checkout, income-linked repayment has no enforcement.
- USP candidates: (A) repayment stream as collateral via payout sweep into an HLBVN account; (B) capped exploration budget to buy real repayment labels; (C) credit ladder that builds the customer's bureau file. Two-lane design: warm lane (pre-computed) + cold lane (eKYC + quick data connect, micro-limit).
- Team still needs to decide: which USP is the headline, and the unit-economics assumptions.

**Caveats.** The cost/time split, the 24% APR, and approval-rate figures are assumptions, not case facts. Regulatory points (Law 91/2025 consent, CIC consent from 1 Nov 2026, eKYC) come from secondary sources and need checking.
